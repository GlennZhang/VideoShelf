# 变更：新增本地视频资料库（第一版）

## 为什么

现有 video_parser 工具只输出分类 JSON，无法对不断增长的中文绘画教学视频（大量来自视频号录屏）进行浏览、搜索和整理。依据 `spec/local-video-library.md` 与 `spec/open-source-video-library-research.md` 的调研结论，没有任何现成开源项目能在不改造的前提下同时满足：原位索引、完整哈希去重、多路径身份、基于 oMLX 的中文语音+视觉联合分析、画家与来源账号区分、人工结果保护。因此在本仓库内自研第一版。

## 变更内容

- **文件夹导入**：支持添加多个文件夹、递归扫描 MP4/MKV/MOV（扩展名大小写不敏感）、手动重新扫描以发现新增/移动/修改/删除的文件；文件不可访问时仅标记为不可用，绝不自动删除人工整理成果。
- **内容身份与去重**：完整文件 SHA-256 作为内容身份；完全相同的文件共用一条内容记录和分析结果，同时分别保存文件路径（文件移动或重复导入后通过哈希重新关联）。（大小，修改时间）仅作为重扫描优化，不作为唯一性证明。
- **媒体分析管线**（经 oMLX）：ffprobe 元信息 → 缩略图/关键帧 → 音频抽取（ffmpeg）→ 中文转写（`/v1/audio/transcriptions`，language=zh）→ 关键帧+转写联合分析（视觉对话模型）→ 标题建议、简介、主分类/主题/视频形式、标签、1～2 张带时间戳的代表截图。无有效语音的视频回退纯视觉分析并显式记录状态。各阶段独立记录进度与错误，支持失败重试，按（内容哈希，管线版本）缓存。
- **画家与来源管理**：画家与来源账号分开保存并带角色（作者/出镜讲解者/被介绍的画家/转载账号）、别名、识别依据和确认状态（未知/待确认/已确认）。支持人工合并与修正，搜索匹配别名。
- **Web 界面（本地 Web 应用）**：FastAPI + 浏览器三栏布局（左：文件夹/分类/画家/合集；中：视频卡片，含截图、标题、画家、短简介、标签、时长、状态；右：详情与编辑）。浏览器内播放、点击截图跳转时间点、定位原文件、编辑画家/标题/简介/分类/标签/备注、收藏、虚拟合集、批量编辑、待确认列表、后台任务进度与重试。
- **搜索**：关键词全文检索覆盖标题、画家及别名、简介、标签、转写（SQLite FTS5 中文可用分词方案）；可按主分类、画家、形式、时长、文件夹、收藏、合集筛选。
- **人工结果保护与存储**：AI 建议与用户修改分别保存；展示层用户值优先，重新分析绝不覆盖用户值。SQLite 为主存储；截图等衍生物缓存在资料库管理目录。提供资料库备份（数据库+截图+转写元信息）与恢复，含跨机器根目录重绑定。原视频永不移动或修改。

**技术选型**：
- FastAPI + uvicorn 本地 Web 应用，仅绑定 127.0.0.1；原生 JS 单页前端，无构建步骤
- SQLite（WAL）+ FTS5 承担存储与中文全文搜索
- ffmpeg/ffprobe 承担元信息、音频抽取、MKV/MOV 的播放转封装/转码
- oMLX（OpenAI 兼容接口，默认 http://127.0.0.1:8989/v1，带 API key）承担转写与视觉文本联合分析
- 顺序执行的单后台工作线程承担分析任务

## 影响

- 涉及规格：新增能力 `folder-import`、`library-storage`、`media-analysis`、`artist-management`、`library-ui`
- 涉及代码：新增 `src/library/` 包（Web 应用、存储、分析管线）；在切实可行处复用 `src/video_parser/` 的帧提取逻辑；`config.yaml` 扩展 `library:` 与 `omlx:` 配置节
- 不做（第二版）：关键时间点、疑似重复检测、学习状态与笔记、系列关联、语义/向量搜索、文件夹自动监控
