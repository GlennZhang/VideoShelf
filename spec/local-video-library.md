# 本地绘画视频资料库需求与选型结论

日期：2026-10-13

状态：讨论结论汇总，作为后续设计和 OpenSpec 变更提案的输入；不表示相关功能已经实现。

## 1. 项目目标

将现有以视觉分类、输出 JSON 为主的视频处理工具，扩展为可浏览、搜索和整理的本地视频资料库。

素材均为中文视频，很多来自对视频号中画家相关内容的录屏。用户添加视频文件夹后，系统建立索引、自动分析并展示结果。原视频保持原位，分类、标签、合集等整理操作不移动或修改原文件。

核心体验：不用完整播放视频，就能通过画家、简介、代表截图和标签判断内容；需要观看时，可以播放视频或跳转至相关片段。

## 2. 运行环境与模型选型

- 硬件：MacBook，M1 Pro，32GB 统一内存。
- 推理服务：oMLX。
- 语言：中文为主，包括可能出现的口音、方言及夹杂的外语专业词。
- 分析方式：语音转写与视频关键帧联合分析。

| 用途 | 初始选型 | 说明 |
| --- | --- | --- |
| 中文语音转写 | `mlx-community/Qwen3-ASR-1.7B-8bit` | 首选候选，兼顾中文能力与资源占用 |
| 视觉与文本联合理解 | `mlx-community/Qwen3.5-9B-4bit` | 必须使用保留视觉权重和处理器文件的完整版 |
| 转写对照测试 | `mlx-community/whisper-large-v3-turbo-asr-fp16` | 用于比较质量、耗时和时间信息 |
| 轻量转写备选 | `mlx-community/Qwen3-ASR-0.6B-bf16` | 吞吐量不足时评估，不预设其质量满足需求 |

调研时，Qwen3-ASR-1.7B-8bit 仓库约 2.47GB，Qwen3.5-9B-4bit 约 5.98GB，Whisper turbo FP16 约 1.62GB。下载大小不等于运行内存；实际峰值受音频长度、图像数量、分辨率、上下文和并发影响。

oMLX 当前上游支持通过 mlx-audio 进行语音转写，并支持视觉模型的多图输入。实际接入前须核实本机版本及依赖：语音走 `/v1/audio/transcriptions`，视觉与文本走聊天接口。中文转写可显式传入 `language=zh`，领域词汇提示需验证版本是否支持。

初始采用顺序处理：转写并缓存，再进行视觉与文本联合分析。暂不预设并发数、处理速度或内存峰值，也不宣称该组合已在本机验证。

## 3. 导入、索引与唯一性

### 3.1 文件夹管理

- 支持添加多个文件夹及递归扫描。
- 第一版识别 MP4、MKV、MOV，扩展名大小写不影响识别。
- 支持手动重新扫描，检测新增、移动、删除和修改。
- 自动监控文件夹的具体实现与扫描频率留待设计阶段决定。
- 添加文件夹后自动排队分析，展示扫描和分析进度。
- 文件不可访问时保留资料库记录，标记不可用，不直接删除人工整理成果。

### 3.2 视频内容与文件位置分离

同一份视频内容可以对应多个文件路径。完全相同的文件共用内容记录和分析结果，分别保存文件位置。文件移动或重复导入后，通过完整哈希重新关联已有记录。

文件内容修改后，应重新计算哈希和判断分析是否失效，不能只依据原路径沿用旧结果。

### 3.3 去重策略

- 推荐完整文件 SHA-256 作为内容身份；MD5 可用于普通去重，但本方案优先 SHA-256。
- 首次导入计算完整哈希；后续可用路径、大小、修改时间判断是否需要重算。
- 对重复候选可先比较文件大小，再比较完整哈希。
- 文件元信息只能作为扫描优化，不能代替完整哈希证明唯一性。
- 重编码、容器转换、元数据修改及重复录屏可能产生不同哈希。
- 同一内容不同版本的识别属于后续“疑似重复”能力，仅提示人工确认，不自动删除文件。

## 4. 自动分析流程

1. 扫描文件，提取媒体元信息，建立内容与位置记录。
2. 提取缩略图、候选关键帧和音频，检测有效语音。
3. 按语音或时间分段转写，保存文本及原视频时间偏移。
4. 将关键帧与对应转写联合输入模型，完成主分类、内容分析、画家与来源信息提取。
5. 生成标题建议、简介、标签和代表截图。
6. 汇总视频级结果，保存识别依据、模型版本及待确认项。

转写应参与初步分类，避免先选错类别后限制后续分析。长视频按段分析后汇总，不能只看开头少数帧或一次塞入全部转写。

无音轨、无有效语音或转写失败时，允许回退至视觉分析并明确记录状态。转写、视觉分析和截图生成等阶段分别记录进度和错误，支持失败重试，复用已完成的有效缓存。

默认每个视频最多转写 300 秒音频：开头 120 秒、约 1/3 处 90 秒、约 1/2 处 90 秒，不固定采样结尾。短于预算的视频完整转写，重叠采样区间合并，时间戳保留视频原始位置。预算通过 `library.analysis.transcribe_budget_s` 配置。已有有效转写缓存继续复用，不因采样策略改变而删除；新采样转写记录覆盖范围，摘要不得声称覆盖完整视频步骤。截图仍按全程采样。

## 5. 分类与内容 metadata

将主分类、主题、形式和标签分开，解决“绘画”和“教程”等类别重叠问题。

示例：

> 主分类：绘画  
> 视频形式：教程  
> 主题：水彩人物  
> 标签：湿画法、肤色调配、入门

| 信息组 | 建议字段 |
| --- | --- |
| 文件信息 | 路径、格式、大小、分辨率、时长、编码、完整哈希、文件状态 |
| 内容信息 | 标题、主分类、主题、视频形式、画种或媒介、工具、技法、标签、简介 |
| 人物与来源 | 画家、别名、来源平台、来源账号、来源与画家的关系、识别依据、确认状态 |
| 文本与时间 | 分段转写、分段起止时间、关键时间点（后续）、代表截图时间 |
| 用户整理 | 自定义标题、备注、收藏、自定义合集 |
| 分析记录 | 任务状态、错误、模型与版本、分析时间、提示词或流程版本、分类依据 |
| 后续学习信息 | 未看／已看／想练习／已练习、个人学习笔记、系列关系 |

技能难度、适用价值等推断项在证据不足时留空或标记不确定，不强行补全。

## 6. 画家与视频号来源识别

- 画家和来源账号分别保存，不能默认发布者就是作品作者。
- 可以从账号文字、水印、字幕、作品落款和语音介绍提取候选信息。
- 不仅凭人脸或画风猜测画家身份。
- 区分作者、出镜讲解者、被介绍的画家及转载账号；必要时支持多位关联人物和角色。
- 信息不足时为“未知”；存在候选但无法确认时为“待确认”。
- 保存候选名称、依据及相关时间或截图，便于用户核对。
- 支持姓名、昵称、视频号名称及别名统一，提供人工合并和修正入口。
- 点击画家可浏览关联视频，搜索支持别名。

例如，“某账号介绍张大千作品”不应将账号主人识别为张大千，也不应将该视频自动认定为张大千本人创作演示。

## 7. 简介与代表截图

### 7.1 简介

- 生成约 100～200 字的内容简介，列表另显示短摘要。
- 说明画什么、使用什么材料或工具、有哪些步骤、讲了哪些具体技法。
- 有依据时补充一句学习价值，例如适合参考哪种处理方法。
- 结合转写和关键帧，避免泛泛描述和无依据推断。
- 支持人工编辑，保留 AI 原始建议。

简介示例：

> 画家示范水彩人物头像，重点讲解肤色调配、湿画法过渡和五官暗部处理。视频包含起稿、铺色及局部刻画过程，可用于参考人物肤色的层次过渡。

### 7.2 截图

- 每个视频提供 1～2 张代表截图。
- 优先选择创作过程与成品画面；没有成品时选择不同阶段的有效过程画面。
- 尽量避开播放器界面、弹窗、模糊帧和重复画面。
- 保存原视频时间戳，点击截图可跳至对应位置播放。
- 支持人工更换代表截图；确实没有两张有效画面时不强行凑齐。

## 8. 浏览、搜索与整理界面

建议布局：左侧文件夹、分类、画家和合集；中间视频列表；右侧视频详情与编辑区。

视频卡片展示代表截图、标题、画家、短简介、分类标签、时长及必要状态。详情展示完整简介、来源账号、转写、文件位置、识别依据和编辑入口。

第一版交互：

- 浏览、播放、点击截图跳转，并可定位原文件。
- 编辑画家、标题、简介、分类、标签和备注。
- 收藏、创建虚拟合集；同一视频可以加入多个合集，不移动原文件。
- 批量指定画家、修改分类、添加标签和加入合集。
- 待确认列表集中处理人物识别不确定、分类模糊及分析异常。
- 展示后台任务进度、错误与重试入口。

搜索覆盖标题、画家及别名、简介、标签和转写；可按主分类、画家、形式、时长、文件夹、收藏和合集筛选。例如搜索“某位画家＋水彩＋人物”。

第一版优先关键词全文检索；语义检索作为后续增强，不要求额外引入嵌入模型。

## 9. 数据存储、人工结果保护与备份

- SQLite 作为资料库主存储，JSON 保留为导出格式。
- 使用全文索引支持内容搜索，中文需明确分词或字符索引方案，不能只依赖默认英文分词。
- 转写、分析与媒体衍生物按内容身份和处理版本缓存。
- 截图等文件保存在资料库管理目录，数据库记录关联关系。
- AI 建议与用户修改分别保存；用户值优先展示。
- 重新分析不得直接覆盖人工修改，可比较新旧建议并选择采纳。
- 提供包含数据库、截图和必要转写信息的备份与恢复。
- 跨机器迁移时支持重新绑定素材根目录，保留内容身份和整理信息。
- 原视频不默认纳入资料库备份，需要明确备份范围。

## 10. 第一版范围与第二版扩展开发

### 第一版

- 多目录递归导入，支持 MP4、MKV、MOV。
- 完整文件哈希去重，内容与路径分离。
- 通过 oMLX 进行中文转写与视觉文本联合分析。
- 主分类、主题、形式、标签。
- 画家与来源账号、别名管理、待确认与人工修正。
- 标题、简介、1～2 张截图及截图时间跳转。
- 浏览播放、关键词全文搜索与筛选。
- 收藏、虚拟合集、备注和批量编辑。
- 任务进度、失败重试、结果缓存及人工结果保护。
- 资料库备份与恢复。

### 第二版：扩展开发

第二版在第一版资料库基础上增强片段定位、学习管理与内容关联，复用已有视频身份、转写、截图和人工整理记录。

| 扩展能力 | 功能范围 | 第一版衔接 |
| --- | --- | --- |
| 关键时间点 | 自动标出调色、五官刻画、成品展示等阶段，展示片段简介，支持点击播放及人工修正 | 保存转写分段和截图的原视频时间，预留时间点结构 |
| 疑似重复 | 提示重编码、不同容器或重复录屏的相似视频，支持人工比较、关联和忽略；不自动删除原文件 | 保留完整哈希、媒体信息和多个文件位置 |
| 学习状态与笔记 | 未看、已看、想练习、已练习；支持视频级和时间点笔记，并按学习状态筛选 | 复用用户备注、收藏及合集，新增字段不覆盖原记录 |
| 系列关联 | 关联上集、下集、同一作品的过程视频及课程，支持排序和人工调整 | 以独立内容身份建立关系，不合并视频或移动文件 |
| 语义与片段检索 | 按自然语言查找相关视频或片段，返回时间范围和依据，保留关键词搜索 | 利用缓存简介、标签及分段转写；嵌入模型与 oMLX 兼容性另行评估 |

第二版验收重点：时间跳转与原视频一致，关联和笔记可备份恢复，疑似重复处理可撤销，语义搜索结果能追溯到实际内容。具体模型、算法与界面在第二版变更提案中确定。

## 11. 实施前仍需确定与验证

- 界面采用本地 Web 应用还是桌面应用；当前未确定框架及打包方式。
- MOV／MKV 等视频的播放兼容方案，必要时生成播放代理文件，保留原文件。
- 中文全文搜索的索引策略及组合查询行为。
- 文件夹监控与重新扫描策略。
- 分类词表、画家角色、人工修改与重新分析的具体交互。
- 在本机 oMLX 上验证模型加载、视觉输入、中文参数、领域词汇提示和时间信息返回。
- 用代表性中文素材比较 Qwen3-ASR 与 Whisper 的漏词、错词、无语音误转写、耗时和内存峰值。
- 比较 Qwen3.5-9B 与现有视觉模型对分类、技法、简介和来源信息的效果。
- 评估背景音乐、视频号界面、录屏水印、长视频、方言及专业术语场景。

本文件是需求与选型结论汇总。进入实现前，按项目 OpenSpec 流程创建具体变更提案、设计、规范和任务清单。
